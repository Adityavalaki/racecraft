# BUG-004: Refresh data shows `DataNotLoadedError` for every new session

**Symptom:** Since about 15 October 2026, Refresh data reports "4 failed", each with
`DataNotLoadedError: The data you are trying to access has not been loaded yet`
(2026 United States GP, FP1 to qualifying). Sessions already in the lake are unaffected.

**Repro:** `racecraft-ingest --season 2026 --rounds 18 --sessions FP1`, before the fix.

**Root cause:** F1's timing archive (`livetiming.formula1.com/static`) answers 401 to requests
without an F1 TV login, for every season (checked: 2023, 2025, 2026 index files; CloudFront
edge rule). FastF1 3.8.3 logs "Failed to load ..." for every feed and leaves `Session.laps`
unloaded, so reading it raises `DataNotLoadedError`, which hides the 401. FastF1 issue #978.

**Fix (step 1 of D-009):** `fastf1_source.load_session` checks, when no laps loaded, whether
the archive answers the session's `SessionInfo.json` with 401, and raises `ArchiveLocked`.
The ingest returns "locked"; the app's sync marks the session "needs F1 TV" and stops asking
F1 for the rest of that pass; the Refresh button says so, with the reason once in its tooltip.
Not a fix for the data itself: that is D-009's free sources (steps 2 to 6).

**Verification:** `tests/test_archive_lock.py` (401 raises; 200, 404 and offline do not),
`tests/test_sync.py::test_once_f1_refuses_one_session_the_rest_are_not_asked_for`,
`SyncButton.test.tsx` ("2 need F1 TV", note once). Real run, 2026-10-26:
`2026_18_FP1: F1's timing archive needs an F1 TV subscription since October 2026`, nothing
written. Full suites: pytest 592 passed (after updating two exact count assertions), vitest
229 passed.
