# BUG-005: `racecraft-ingest --radio` crashes on a lake that already has sources

**Symptom:** The first real run of the team radio backfill (D-014), 2026-10-27, stopped at the
first session it tried with `ValueError: 7 columns passed, passed data had 4 columns`. Nothing
was written: it failed before its first write.

**Repro:** `racecraft-ingest --radio` on a lake where at least one session has a `sources`
table (any session ingested since D-013) and another, older session has none.

**Root cause:** `backfill_radio` read the existing source rows with `select * from sources`.
In the lake's database every table also carries its partition columns (year, round,
session), so that gave seven columns; a session with no rows of its own then got a fallback
row built with those seven column names but four values. The test's small lake had no
`sources` table at all, so it took the other branch and passed.

**Fix:** Name the four columns in the query (`ingest/cli.py`, `backfill_radio`).

**Verification:** `tests/test_team_radio.py` now builds a lake that already has a `sources`
table (an OpenF1 session with source rows, beside a FastF1 session without): both gain
their radio, and the OpenF1 session's own rows are kept. It fails on the old query. Then the
real backfill was run on the lake (results in the commit and HANDOVER).
