# BUG-002: Cached model fits went stale after an ingest from another process
Symptom: With `racecraft-serve` in a browser and `racecraft-ingest --watch` adding a race, the
next race's pit loss and tyre wear still left the new race out until the server restarted. A fit
that was running while the app's own sync finished was stored after the caches were cleared.
Repro steps: build `insight._season_fits(2026)`, ingest a 2026 race from a second process, ask
again: the old fit came back. (Now covered by `test_new_sessions_change_the_key_every_model_cache_uses`.)
Root cause: caches were keyed by the lake's path only and cleared by `sync_view.forget_models`,
which only the in-app sync called; `insight._answer_cache` was never cleared at all.
Fix: `store.db.lake_key()` returns (path, version); the version goes up whenever `connect` reloads
a table, whoever wrote the files. Insight, places, tyre-set and title caches use it in their keys.
`forget_models`, the Syncer's `on_written` hook and the duplicate `tyre_sets_view._weekends` cache
are deleted. `race_inputs._race_cache` stays path-keyed (shortcut comment there). D-002.
Verification: sync, insight, tyre sets, title, live, API, places, lake and race-input tests:
172 passed.
