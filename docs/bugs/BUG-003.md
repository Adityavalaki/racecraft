# BUG-003: Opening a session loaded it several times at once
Symptom: Opening a session fires info, laps, state and messages together; each request that
missed the cache loaded the whole session (about 800,000 telemetry samples) itself, so a race
was held in memory four or more times at once. The 15-second season fit had the same gap when
the main window, a pop-out and the pit windows asked together.
Repro steps: four threads calling `session.load("2024_01_R")` at once ran four loads
(`test_requests_arriving_together_load_a_session_once`).
Root cause: check-then-load with no record of a load in progress.
Fix: the in-flight Event pattern from `places_view`: the first caller loads, the others wait
for it and read the cache. Applied to `session.load` and `insight._season_fits`. D-003.
Verification: API, insight, live and telemetry tests: 78 passed.
